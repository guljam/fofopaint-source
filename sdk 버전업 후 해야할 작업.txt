AIR SDK 버전업 후 해야할 작업
=============================
(예: 51.4.1 -> 51.5.0 으로 올리는 경우. 새 SDK는 D:\adobe_air_sdk_manager\AIRSDK_51.5.0 에 풀어둔 상태라고 가정)
(Main/AboutWindowSet의 표시용 SDK 버전은 이미 알고 있으므로 제외, 아래 1번에 위치만 적음)

[A] 최신 SDK 경로 (디버깅 F5 + 번들 + ANE) - 아래 6곳의 "AIRSDK_51.4.1"을 새 폴더명으로 변경
 1. build-main.ps1            10행  $sdk = '...\AIRSDK_51.4.1'      메인 SWF 컴파일(F5)
 2. build-worker.ps1           6행  $sdk = '...\AIRSDK_51.4.1'      worker SWF 컴파일(F5)
 3. make-air-bundle.ps1       13행  $sdk = '...\AIRSDK_51.4.1'      번들 release 컴파일(메인+worker) + adt 패키징
 4. anesrc/fofonative/build-ane.ps1  16행  $sdk = '...\AIRSDK_51.4.1'   ANE 빌드(include/lib, acompc, adt)
 5. .vscode/launch.json       12행  runtimeExecutable = ".../AIRSDK_51.4.1/bin/adl.exe"   F5 실행 adl
 6. .vscode/settings.json      2행  "as3mxml.sdk.framework": "...\AIRSDK_51.4.1"        VS Code 확장(코드 힌트/컴파일 SDK)

[B] 이름에 버전이 들어간 문구
 7. .vscode/tasks.json        86행  label "Make AIR Bundle (x86 + x64, SDK 51.4.1 runtime)" 문구
    (label만 바꾸는 것이라 dependsOn 등 다른 곳에서 이 label을 참조하는지 확인)

[C] 네임스페이스 (메이저.마이너만 따라감, 예: 51.4 -> 51.5. 패치 버전만 오르면 변경 불필요)
 8. fofoPaint-app.xml         19행  <application xmlns="http://ns.adobe.com/air/application/51.4">
 9. anesrc/fofonative/extension.xml  1행  <extension xmlns="http://ns.adobe.com/air/extension/51.4">
    - ANE extension 네임스페이스는 앱 descriptor 네임스페이스보다 높으면 안 됨, 두 값을 같이 올릴 것
10. make-air-legacy.ps1      23행  -replace 'http://ns\.adobe\.com/air/application/51\.4' -> 새 번호
    (앱 xml 네임스페이스를 51.3으로 낮추는 변환의 "원본 패턴"이라 8번과 같은 값으로 맞춰야 함. 안 맞으면 변환이 안 됨)
11. make-air-legacy.ps1      주석 1~5행  "51.4" 설명 문구 (동작에는 영향 없음)

[D] 바뀌지 않는 값 (SDK가 올라가도 새 기능을 쓰려는 게 아니면 그대로)
 - -target-player=51.1, -swf-version=51  (asconfig.json, build-worker.ps1, make-air-bundle.ps1, make-air-legacy.ps1, build-ane.ps1의 acompc)
   새 SDK의 swf-version이 52 이상으로 올라가면 그때 전부 같이 변경
 - make-air-legacy.ps1의 $legacySdk (51.3.4): 공유 런타임 배포용이므로 최신 SDK와 무관, 의도적으로 고정

[E] 선택 (개발 도구용, 앱 빌드와 무관. 쓸 때만)
 - anesrc/pigmentmix/build-ane.ps1, anesrc/pigmentmix/test/run-test.ps1, repdata_parser/run.ps1 : AIRSDK_51.3.4 사용 중
 - anesrc/pigmentmix/test/PigmentMixTest-app.xml(51.1), repdata_parser/ReplayParser-app.xml(51.3)

[F] 버전업 후 확인
 1. Main.as/AboutWindowSet.as의 표시용 SDK 버전 문자열 갱신 (이미 알고 있는 부분)
 2. 해시 기반 재빌드는 SDK 경로가 해시에 들어 있어서 경로를 바꾸면 자동으로 다시 빌드됨
    - fofoPaint.swf.srchash(build-main), worker.swf.srchash(build-worker, 저장소 추적), extension/com.fofo.nativecore.ane.srchash(저장소 추적)
    - 폴더명이 그대로인 채 SDK 내용만 덮어쓴 경우엔 자동 재빌드가 안 되므로 build-main.ps1 -Force 로 강제 빌드, 나머지는 srchash 삭제
 3. 새 SDK 의 FlashRuntimeExtensions.lib, include 가 바뀌었을 수 있으니 ANE(x86/x64)가 정상적으로 다시 빌드되는지 확인
    -> 변경된 worker.swf, worker.swf.srchash, extension/com.fofo.nativecore.ane(.srchash)는 같이 커밋
 4. F5 디버깅 실행 -> 번들 x86/x64 생성 -> 번들 실행 확인
 5. .air(legacy)는 51.3.4 고정이므로 영향 없음. 단 앱 xml 네임스페이스를 올렸으면 make-air-legacy.ps1 변환(10번)이 되는지 확인
 6. InputManager.as 의 ALT 입력 관련 주석에 적힌 "AIR 51.4.1부터" 같은 역사 설명은 바꾸지 말 것(그 시점부터 동작이 바뀌었다는 기록)
