# 작업 지시서: line4 점별 시각을 10초 연출 길이 안에 맞추기 (2026-10-07)

기준 커밋: 801e2b5
관련 검토: [REVIEW-23-27-37.md](REVIEW-23-27-37.md) 1번 문제점 1

## 배경 / 문제

- b4d6127에서 도구 연출 길이를 `ANIM_COMMAND_TIME_LIMIT_MS`(10000ms)로 제한함 (`ReplayState.stampTimingSheetToolCommand`)
- line4의 점별 시각(`points`)에는 제한이 적용되지 않아서, 도구 시작 기준 실제 ms가 그대로 저장됨 (ReplayState.as:134)
- 재생할 때 `ReplayAnim.startLine`은 `recorded[i] > totalMs`인 값이 하나라도 있으면 기록된 시각을 버림 (ReplayAnim.as:243)
- 결과: 선 도구를 10초 넘게 쓰면 녹화된 점 순서 타이밍을 잃고, 경로 길이 비례 방식으로 대신 재생됨

## 목표

선 도구를 10초 넘게 써도 저장된 점별 시각이 모두 `0 ≤ points[i] ≤ 연출 길이(≤10000)`이고 앞에서부터 줄어들지 않음 → 재생에서 기록된 시각이 쓰임

## 방식: A안 비율로 줄이기 (확정)

- 식: `실제 걸린 시간 > 연출 길이`이면 `points[i] = Math.round(points[i] * 연출 길이 / 실제 걸린 시간)`
- 재생 모습: 점을 찍은 리듬(상대 간격)이 유지되고 전체가 빨라짐
- 반올림해도 값이 줄어드는 순서는 생기지 않음 (단조 증가 함수)
- 채택하지 않은 안(B, 10초에서 자르기)은 10초 이후 점들이 연출 끝에 몰려서 제외함

## 수정 범위 (이 파일 하나)

`src/Modules/ReplayEngine/ReplayState.as` — `stampTimingSheetToolCommand`만 수정

1. 실제 걸린 시간(`getTimer() - startStamp`)을 **points 계산보다 먼저** 구함 (지금은 points를 먼저 만들고 길이를 나중에 계산함)
2. 연출 길이 = 실제 걸린 시간을 `0 ~ ANIM_COMMAND_TIME_LIMIT_MS`로 자른 값 (지금 동작과 같음)
3. points 계산: 지금처럼 `Math.max(0, (pointStamps[i] - startStamp) | 0)`를 구한 뒤,
   - 실제 걸린 시간이 연출 길이보다 크면 `Math.round(값 * 연출 길이 / 실제 걸린 시간)`
   - 마지막에 `Math.min(값, 연출 길이)`로 한 번 더 막아서 반올림 등으로 넘지 않게 함
4. 지역 변수 `endStamp`는 의미가 걸린 시간이므로 이 기회에 `animMs`로 이름을 바꿈 (이 함수 안에서만 쓰임)

수정하지 않는 것:
- `ReplayAnim.startLine`의 검사 (옛 데이터가 맞지 않으면 버리는 안전장치로 남김)
- `TimingSheetFile` 저장 형식, `LineTool`의 `pointStamps` 수집
- 이미 저장된 옛 데이터의 변환 (범위 밖. 옛 파일은 지금처럼 경로 길이 비례로 재생됨)

## 검증

헤드리스 하네스 `test-output/realtime_rec` (빌드: `build.sh`, 실행: `run.sh <phase>`)

1. **새 케이스 추가**: `pushLine4`와 같은 모양으로, 도구를 20초 전에 시작하고 점 시각을 `[now-20000, now-15000, now-5000, now-100]`으로 기록
   - 기대: `animMsOfFrame` = 10000, `pointOffsetsOfFrame` = `0,2500,7500,9950`
   - 값이 줄어드는 곳이 없고 모두 10000 이하
   - 주의: 하네스에서 `now` 이후 getTimer가 몇 ms 흐르면 실제 걸린 시간이 20000보다 조금 커져서 값이 ±1~2 달라질 수 있음. 정확히 비교하려면 허용 오차를 두거나 시작 시각을 `getTimer()` 직전 값으로 계산할 것
2. **기존 케이스 회귀 확인**: `pushLine4`(3초짜리)의 점 시각이 예전과 같은 `0,200,1800,2800`인지
3. 메모리 경로와 파일 경로(파일로 밀어낸 뒤 rebuild) 두 곳에서 같은 값이 나오는지

참고: 같은 하네스의 `animTest`는 15초 이동을 기록하고 `anim (want ~15000)`을 기대한다고 적혀 있음. b4d6127 이후에는 10000이 맞으므로, 결과를 볼 때 이 줄을 실패로 보지 말 것 (기대값 문구 정정은 이 작업과 별도)
